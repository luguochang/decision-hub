# Decision Desk 用户体验复盘与改版方向

日期：2026-09-26。依据本机运行的 `http://127.0.0.1:8047/`、1280×800 桌面与移动端截图，以及 [研究智能体产品规格](RESEARCH_AGENT_PRODUCT_SPEC.md)。本次是设计诊断，尚未将下述目标状态视为已实现。

## 产品应如何工作

Decision Hub 的主流程是：用户一次性设定研究范围 → 系统持续监控授权来源 → 自动识别值得研究的变化 → Agent 补证、复核并生成有边界的报告 → 主动呈现变化与下一次复核时间。用户日常只需看变化、判断结论和必要时反馈。手动输入用于临时问题、补充约束或追问，不应是每天获得研究结果的前提。研究结论不构成自动交易许可。

当前实现有调度器、自动复核、持久任务和 DSH 研究执行，但首页以空输入框和“获取最新操作建议”为主行动，用户自然会理解为必须亲自提交研究。2026-09-26 本机 API 最近 100 条 Run 中，97 条为 `scheduled_recheck`、3 条为 `manual`，均为 `research_only`。这证明自动复核在运行，不足以证明近期已有独立发现的新事件。不能把“自动复核很多次”表述成“已主动发现很多重要事件”。

## 截图中明确的问题

| 位置 | 当前表现 | 用户的实际困惑 |
| --- | --- | --- |
| 首页 | 大幅品牌头图、手动研究输入、手动 CTA、三个指标、远期日历、Run 列表和报告同时竞争首屏 | 应先看什么、系统今天主动做了什么都不清楚 |
| 手机首页 | 桌面模块依次纵向堆叠 | 有效结论被推到很长的滚动之后 |
| 报告 | 日历与任务列表占据结论上方的大块区域 | 打开报告后不能立刻读到结论、依据与限制 |
| 资料页 | 两层头图、两套上传流程提示、两处上传按钮 | 不知道从哪个入口开始，也不知道当前资料处于哪一步 |
| 全站文案 | `Research Runs`、`Run ID`、`provider`、`durable`、`source_unavailable`、原始来源 ID 等混用英文和内部枚举 | 用户需要理解工程概念才能完成普通操作 |
| 内容排序 | 验收 fixture 的长标题和测试要求出现在最近报告与资料列表 | 测试记录占据了真实使用入口，并影响用户对结论的信任 |
| 导航 | “组件与状态”“页面与状态目录”“交付说明”等设计验收入口面向普通用户出现 | 设计包中的 38 个状态被误当成 38 个用户功能 |

此前按页面可打开、按钮可用、Run 可提交完成的是功能联调验收，不能替代用户体验验收。上述混乱是信息架构与默认内容的问题，单纯缩小卡片或改中文标签无法解决。

## 建议的默认信息架构

主导航保留三个用户目的：

1. **今日研究**：系统最近发现的变化、正在研究的重点、最新可读结论。无重要变化时明确显示“监控正常，暂无值得新增研究的事件”，并展示最后检查时间。
2. **研究报告**：按事件归并后的报告历史。默认展示主题和结论，不把每次复查当成一篇新报告；同一事件的历史版本和复核记录可展开。
3. **关注与资料**：持续关注范围、资料上传与审核。资料只出现一次清晰的状态流程。

日历、证据详情、来源健康、Run/DSH 轨迹仍可访问，但作为上下文详情或高级诊断。组件状态、页面目录和交付说明从普通用户导航移出，保留内部验收入口。

## 页面优先级

### 今日研究

首屏依次回答四个问题：系统是否正在监控；自上次查看后有什么重要变化；最新结论是什么；下一次何时复核。最多展示少数高相关事件。主要行动是“查看这份研究”，次要行动才是“临时研究一个问题”。不要用“留空也能开始研究”解释自动化；留空仍然是在让用户发起任务。

### 研究报告

标题下直接显示结论、适用时间、关键依据、反方证据、尚缺什么以及复核条件。`research_only` 面向用户解释为“仅供研究，暂不能执行”，不能用证据覆盖 100% 暗示交易结论已充分。日历和其他任务不出现在报告正文前。证据条目可展开；原始 ID、模型轮次、工具调用、成本及 Runtime 放入“技术与审计”。

### 关注与资料

统一上传入口与单条进度；默认显示资料名称、用途、审核状态和下一步。修正、质量复检和版本血缘仅在相应资料详情展开。验收资料应使用隔离数据库或明确的测试标记与默认列表过滤；保留审计记录，但不占用正常用户的最新报告。

## 实施与验收顺序

1. **先隔离验收数据并修正默认排序**：普通首页、报告列表、资料列表不显示 fixture；正常研究历史仍可追溯。若当前没有有价值的新研究，如实呈现空态。
2. **重建首页和报告首屏**：把自动监控、变化和结论置顶；手动研究改为次级入口；手机首屏也能看到结论或明确空态。
3. **统一文案与渐进披露**：主要页面使用中文业务词；原始枚举和 ID 收入诊断层；状态都解释其影响和下一步。
4. **验证自动发现的真实闭环**：用非手动来源事件演示发现、准入、补证、报告及复核，并观察它是否被正确排进“今日研究”。自动复核与人工触发分别统计，不混为主动发现。
5. **再做追问交互**：允许从报告提出“为什么结论变化”等问题，保持报告、证据和 Run 的关联；只有端到端能力可用后才对用户展示该入口。

验收不以页面数量或状态覆盖率为准。让首次使用者在不读文档的情况下，30 秒内说清“系统正在做什么、今天发生了什么、我该看哪份结论、手动输入是做什么的”；报告打开后首屏能看到结论与限制；技术字段不进入默认阅读路径。
