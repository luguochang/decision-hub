# ADR-0025：Decision Desk 作为日常研究入口，DSH Web 保留原生执行与审计

日期：2026-09-27  
状态：**当前单 owner 本机产品已采用；完整真实事件验收仍按产品门槛执行**

## 背景

ADR-0013 将 DSH Web 设为交互主壳，以便直接使用官方 Session、插件和工具轨迹。现有产品已形成来源、事件、资料、Run、报告、预测与运行账本。用户日常需要先了解系统主动检查、研究结果及受限原因，而 DSH Web 的原生视图以执行过程为中心。UX V3 评审因此把“今日研究、市场与事件、研究、资料”组织成业务入口，同时明确所有原有能力要可达。

## 决定

1. **日常入口**是 Decision Desk 的 `#/home`。首页只从持久账本和实时状态投影读取事实；没有新研究就显示真实空态。手动发起研究是次级动作。
2. **执行与技术轨迹**仍由官方 DSH Web 及其插件拥有。Decision Desk 不复制 DSH 的 Session 状态、工具权限、模型路由或对话执行器；报告和任务按同一 Run ID 下钻到技术轨迹。
3. **业务状态**由 Hub API/Kernel 拥有。Decision Desk 展示事件、Run、资料版本、来源尝试、DataJob、Evidence、Gate 和 Outcome；命令走现有 owner 审计接口。列表与深链接使用稳定身份及服务端分页。
4. 当前范围是 **BTC / 宏观、单 owner、本机运行**。黄金和多用户不因出现导航结构而获得执行权限。`X-Owner-Id` 不能当成远程用户认证。
5. 旧 `#/Inbox`、`#/Operations`、`#/Evolution`、报告/证据、日历和资料深链保留。设计状态目录仍可在管理与审计下访问。

此决定只调整**用户入口与信息架构**，不废止 ADR-0013 关于官方 DSH Web、插件和上游兼容的执行边界。此前文档中“DSH Web 是唯一日常入口”的描述由本 ADR 在当前本机产品范围内取代。

## 代价与验收

- 两个界面必须指向同一 Run、同一 Evidence 与同一时间语义；业务摘要不能将技术进程在线误作真实研究报告可交付。
- 冷启动、来源降级、Worker 离线、Run 失败、资料跨域、旧深链、桌面/手机与重启回读均需验收。生产能力的完成标准仍以[全项目 PRD](../product/DECISION_HUB_FULL_PRODUCT_PRD_2026-09-26.md) G0–G4 为准。
- 只读设计原型中的示例、未来黄金概念和待办汇总不得进入生产数据或伪装成已上线能力。
