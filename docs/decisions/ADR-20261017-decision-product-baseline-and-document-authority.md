# ADR-20261017：事前决策产品基线与文档适用范围

日期：2026-10-17。状态：review-4业务/市场选择已获用户确认；review-5补审条款为proposed，当前按用户最新指令暂停实施。未修改现行wire、数据库或运行配置。

## 背景与已确认事实

用户先明确“按这个方案来，OKX永续的建议和纸面验证也按推荐方案”，随后要求再核对并修订全部相关文档、确认后再执行。先前批准事实保留，后续暂停控制当前动作。不能把暂停写成用户从未确认，也不能拿历史批准越过新暂停。

现有README/INDEX/context包含多个历史“当前/下一阶段”，旧治理规范要求每次重构全量检查和每个冲突重新问owner，旧运行手册示例含gpt-5.5。这些与当前BTC/ETH主线、gpt-6.1-sol和有界执行计划存在适用范围冲突。

## 决定与继承

1. 当前产品目的/批准/暂停由[00总控](../design/decision-product-control-2026-10-17/00_MASTER_CONTROL.md)记录；05负责唯一任务顺序和执行合同；06保留决策/操作历史。用户最新明确指令优先，不能以旧文档把已授权的普通工程决定再次变成审批阻断。
2. 既有ADR的owner隔离、PIT、原件认证、Agent不得直接发布/交易、单writer、schema/codegen、迁移不可改历史继续有效。本ADR不提供绕过这些边界的权限。
3. 现行canonical schema证明当前实现，不会自动否决已批准的新版本设计。新设计经版本化schema、reader/生成类型/迁移及消费者共同落地后才变成当前实现；不得改旧字段含义冒充兼容。
4. 旧R0/R1/R2、spot-only、30m和Provider示例属于各自范围；新perp、4h、事件族按新合同增加，不覆盖历史成绩。DSH内循环/Graph外编排/Hub权威分工按07/08细化，旧框架复用清单不强迫再嵌套第二个Agent循环。
5. 开发验证以批准任务的直接门和影响面为准；正式候选做必要整体回归。相同代码/配置/有效输入不重复检查，文档低影响编辑不制造镜像测试，不能以旧“全量检查”无限扩围。
6. 工程负责人可处理不改变产品/概率/身份语义的内部决定并记录。改变用户范围、风险语义、真实交易权限或产生新费用时才提交具体取舍。当前恢复实施仍等待用户结束本次文档复核暂停。

## 后果与复核

采用一份当前导航及有界读集，旧原件/历史决策继续可查。风险是遗漏旧要求，因此01保留原需求映射，改变语义须登记被替代的具体条目；不能仅写“旧文全作废”。新数值参数、运行SLO、研究与paper扩充见review-5各合同，不因本ADR获得运行或金融通过资格。

实施门和开发入口见[12工程就绪与交付](../design/decision-product-control-2026-10-17/12_ENGINEERING_READINESS_AND_DELIVERY.md)。未来恢复后应更新本ADR的批准范围与证据，不重写本次暂停记录。
