# 研究主题、真实事件与报告版本

状态：已实现，正式验收结果以 [执行台账](../plan/ARCHITECTURE_REMEDIATION_EXECUTION_LOG.md) 为准。

## 决定

- `Occurrence` 只负责身份，事件日期、时间、值和修订仍以 `MacroEvent/Vintage` 为权威。来源稳定 UID 或原文 URL 可连接多个观测版本；HTML 以日期构成的旧键标为 `calendar_key_provisional`，没有官方会议批次时不猜测跨日期身份。
- `Study` 的范围包括问题、市场、品种及窗口。固定“BTC 最新观察”入口沿用同一持续主题；独立问题按不同来源事件/原文建立主题。历史无法明确范围的记录标为 `legacy_unknown` 并默认暂停，需明确关注后才自动复查；父子 Run 沿用已知关系，不按同一个 event_type 自动合并。用户主动单次重试可以查看暂停主题，且不自动恢复持续关注。
- `Run` 是执行，`ReportRevision` 是不可变输出；版本与 Artifact 在同一次发布事务写入，按同主题及策略连接前版。版本记录输入指纹、原报告时间、实际建立映射时间和摘要/证据内容变化。内容哈希去重不是“独立来源数”。
- 复查只由同一 Study 的最新完成根 Run 授权，子任务不再自建复查树。日期型、撤回、取消日历不产生精确时刻复查。失效事实必须属于相同主题的 Run，旧记录按明确 event_id 保守隔离。
- 自动准入保存策略版本、命中词、准入/合并/忽略/预算阻止原因；研究准入预算和 Run 在同一事务。当前确定性标题规则如实标明，不称其为模型理解。默认滚动 24 小时最多 12 个自动研究，每 Study 每小时最多 2 个；baseline 兼容任务不充当 AI 研究成功。
- API 手动抓取和常驻 Worker 共用同一策略。`POST /v1/sources/{source_id}/poll?mode=catchup` 可补看默认近 7 天、最多近 30 天的最新一条重要公告，不回退实时游标；无合格公告返回空结果。有据可查的历史补看不算前瞻预测样本。
- 同 UID、同计划时刻仅文案修订，不重复安排 Watch/Run；改期撤销该 Occurrence 已等待计划并保留旧样本。真正释放/修订的信息仍追加独立观测版本。

## 迁移与接续

0049 只增表/列。先停止受管产品，备份后调用 `tools.ops.backfill_studies`；它两次投影验证幂等，并核对原 Artifact、Forecast、Evidence、Fact、Result、Observation、Vintage、Watch、Sample 的完整行哈希。副本预演结果不等于正式迁移。

新增只读接口：`GET /v1/studies`、`GET /v1/studies/{study_id}`、`GET /v1/runs/{run_id}/study`、`GET /v1/discovery/decisions`，含分页和筛选。旧 Run/报告/证据地址保持可读。用户可视主题入口与关注开关属于 W6，尚不以本 ADR 宣称已经完成。

## 边界

政策修订、预算被阻止的条目有可查决定，但不会静默越过预算补跑；后续主动触发策略的效果需单独用冻结漏报/误报样本评估。来源 URL/UID 只能证明来源对象一致，不必然证明不同机构描述的是同一个真实事件。旧记录没有真实原始凭据时保留未知。本文替代旧“按事件类别保留唯一复查根”的规则，其余审计与质量门保持。
