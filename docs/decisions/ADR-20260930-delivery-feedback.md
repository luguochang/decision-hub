# ADR：版本交付、已读与跟踪命令

日期：2026-09-30。状态：0052 已正式部署；版本回执/反馈已真实验收，追踪在隔离副本完成浏览器验收；W7.2 已在隔离副本完成真实候选、回放与留出执行，真实前瞻评测仍未通过。具体结果以执行台账为准。

## 问题

Outbox.sent_at 只能证明适配器完成本地投递，不能证明用户看到报告；现有反馈指向 Run，页面缺少明确版本；Study 有 active/paused 状态但缺少可审计操作入口。

## 决定

1. 产品收件箱使用不可变 ReportRevision 身份。local_written、外部渠道回执和明确标记已读分开显示；无已读记录就是未标记，不回填旧用户阅读时间。
2. 已读/未读为显式操作，可恢复。每次操作有 Owner、幂等请求、报告版本及时间回执。打开 API 或自动验收读取不自动替用户标记已读。
3. 轻反馈指向 report_revision；沿原 Run 关联进入研究价值和经验候选输入，反馈不直接晋级策略，不修改原报告。
4. 跟踪 active/paused 使用带预期旧状态的命令及幂等回执。暂停阻止后续自动复查；已执行的任务正常收尾；已排队自动复查按明确原因停止。未知范围旧主题不能直接开启，先明确品种和研究范围。
5. 暂停与调度需在入队时再次核对状态，防止页面暂停后旧扫描快照继续创建 Run。恢复只处理仍适用的窗口，不把过期计划重放成新研究。
6. 经验候选必须固定评测集/版本与 Owner 审查后才能晋级；可回滚指针。W7.2 需单独验证现有演进运行时，不把 fake fixture 或单条反馈当真实学习成功。

## 验收门

未授权拒绝；重复请求不重复写；同请求换载荷冲突；跨版本不串已读/反馈；不存在版本 404；暂停/调度竞争不会新建自动任务；旧反馈/Outbox 数据原样保留。先副本迁移和回归，再正式部署和真实浏览器验证。
