# Decision Hub PC 用户手册

更新：2026-10-23（北京时间）。本文件是当前唯一用户手册；原文件名保留，方便已有书签继续使用。

**当前为验收版，尚未通过 BTC／ETH 真实报告、建议与模拟成交的完整验收，不能视为已交付。**
设置、任务受理、报告发布、审核授权与模拟成交是不同结果，必须逐项核对。
本手册只说明 PC 本机操作；以下示例使用模拟资金，不连接真实下单。

### 事件情景预案怎样阅读（49集成说明，PC真实验收尚未完成）

有事件预案的已保存报告会把“普通方向预测”与“事件情景预案”分开展示：

- **情景发生概率**：在该事件发生的条件下，各种公布结果分别有多大可能。
- **条件方向概率**：假设这一情景发生，BTC或ETH在指定时间窗上涨、区间内、下跌的概率。它和情景本身的概率含义不同。
- **根因依据、反证与未知项**：判断依赖哪些事实和假设，以及哪些信息缺失；缺失不会自动补成事实。
- **确认与期限**：什么时候、用什么数据确认情景；方案何时失效。旧报告保留原来的时点和窗口。
- **持仓预案详情**：空仓、已有多仓、已有空仓是互斥的账户情况，应阅读与你实际账户相符的方案。研究比较单位不等于已授权的下单数量。

事件公布后，系统可以匹配事前已审核的分支并更新建议。分支匹配仍需核对当前报价、账户和风险设置；模拟执行以实际确认后的成交回执为准。报告等待核对时无需重新提交研究，离开页面会取消当前读取，原研究和报告保留。

## 1. 这个产品用来做什么

Decision Hub 将截至研究时点可取得的资料组织成事前判断：未来一段时间可能怎样变化、概率和依据是什么，以及什么条件下应行动或等待。
阅读时同时看概率、证据、适用账户、成本假设、限制与失效条件；不要只看方向或一个分数。
方案用于帮助你比较开仓、维持、退出或不操作，不能把预测概率理解为保证收益。
研究会保留原任务和证据，便于事后检查“当时知道什么”；旧报告不会自动变成当前行情。

| 你要做什么 | 从哪里开始 | 完成时核对什么 |
| --- | --- | --- |
| 按账户风险研究 BTC | 今日研究 → 查看已保存设置并研究 | 保存设置回读、原研究进度、同一次研究的报告和建议 |
| 阅读依据或旧研究 | 原研究进度、研究、历史研究回执 | 原任务编号、研究时间、证据新鲜度与限制 |
| 验证一笔模拟操作 | 有效建议中的手动模拟区 | 独立授权、实际成交回执、退出及结算 |
| 查看资料、事件或运行情况 | 资料、市场与事件、管理与审计 | 来源、版本、时间及原记录 |

## 2. 打开本机入口并确认身份

1. 使用启动器创建的 **“Decision Hub”本机快捷方式／私有入口**，在 Chrome 打开。
2. 工作台地址是 [本机今日研究](http://127.0.0.1:8047/#/home)。直接打开此地址不保证已经连接本机身份。
3. 进入设置后，等待页面显示“当前身份”和“本机授权有效至”，再操作账户或提交研究。
4. 身份缺失或过期时，重新打开正常本机入口，等待配对和身份回读完成；不要在配对过程中立即刷新或提交。
5. 已完成连接但旧页仍未更新时，可完整刷新一次，再等待身份核验与账户回读完成。
6. 若入口不可访问，交由本机维护人员恢复；不要自行更换端口、重建账户或清空浏览器记录。

“API 与研究进程 3/3”只说明当时的运行状态，不表示已有报告、审核通过或模拟成交。
恢复身份后仍应回到原任务核对；不要把身份错误当成“原请求肯定没提交”。

## 3. 选原模拟账户并保存风险设置

从“今日研究”点击 **“查看已保存设置并研究”**，进入“仓位与风险设置”。

1. 在“账户来源”选 **“已保存的模拟账户”**，选择原 **“模拟账户 1”**。
2. 点击“重新读取模拟账户”，核对原账户、当前仓位、权益和可用保证金；示例为 **空仓、2500 USDT／2500 USDT**。
3. 在“合约”选择 BTC 永续合约 `okx:BTC-USDT-SWAP`；若缺少选项，先按页面提示“读取 BTC 合约元数据”。
4. 示例“最大名义暴露（USDT）”填 **500**，“最大计划损失（USDT）”填 **25**；按自己的授权选择“允许方向”。
5. 点击 **“保存设置”**，再点 **“重新读取设置”**，核对服务端回读的账户、合约、版本、500 和 25。
6. 研究期限选择 **4 小时**。先确认保存的版本正确，再发起研究。

500 是名义暴露上限，不是必须投入的金额；25 是计划损失约束，不是任何市场情况下的损失保证。
模拟账户余额和仓位由账本维护，不要为凑示例改成“用户自报”，也不要另建账户绕过余额或结算问题。
需要新建账户时，“创建模拟账户”另有确认流程；创建成功本身不会开仓。

## 4. 只发起一次研究，保留原请求

1. 首次点击 **“研究 BTC 4 小时方案”**。
2. 同一份设置已有历史研究时，按钮可能是 **“重新研究当前已保存设置”**；设置已变时可能是“按当前已保存设置发起新研究”。
3. 一次点击后等待原结果；研究可能产生新的模型用量，**不要反复点击或重新提交**。
4. 显示“研究请求已接受”后，点击 **“查看原研究进度”**，继续看同一次研究。
5. 保存当前页或任务链接，保留原请求编号；不要用列表中“最新的一条”替代自己的原任务。

受理只表示服务器接受研究请求，不表示报告已保存、金融审核通过或开始模拟成交。
若页面显示提交结果待确认，使用 **“核对原研究回执”**，只读取原请求结果，不另发新研究。
若明确显示原请求未受理，先按页面的“关闭未受理的原请求”完成核对；不明确时请维护人员协助。

## 5. 看原研究进度、证据和历史回执

进度页显示当前任务与报告状态。研究中可点 **“查看已收集的证据”**，再返回原进度。
证据条数、已完成工具调用和“准备成功”都不等于最终报告或审核通过。

| 页面状态 | 你应怎样处理 |
| --- | --- |
| 研究进行中 | 等待原任务；可阅读已收集证据，不重新提交 |
| 阅读研究报告 | 进入当前任务对应的报告，核对任务与设置版本 |
| 本次研究未完成 | 点“查看原因与恢复”，保留失败原件 |
| 等待建议发布／尚未形成建议 | 暂不能据此准备模拟操作 |
| 结果待核对 | 读取原回执，不能先当成功或失败 |

**“历史研究回执（N）”默认折叠。** 需要旧任务时再展开，按原请求编号“核对历史回执”，随后“查看历史研究进度”。
历史回执恢复成功只证明找到了原请求，不证明研究完成，也不会把旧设置变为新预测。
想停止正在进行的任务，可在原进度页使用“停止本次研究”，按提示确认并等待真实终态；关闭标签页不等于停止。

## 6. 怎样阅读同一次研究的报告和建议

**本轮完整成功报告、建议发布与对应截图：待验收。以下是阅读顺序，不是成功证明。**

1. 从原进度的“阅读研究报告”或建议中的“追溯原研究报告”进入，核对是同一次任务。
2. 先看合约、账户、保存设置版本、研究时间和 4 小时窗口，防止读到另一账户或旧方案。
3. 看事前概率、方向、主要依据、相反证据、未知项与适用条件，不只看一句结论。
4. 展开来源与证据，分别核对发布时间、事件时间、系统取得时间及新鲜度；采集失败记录也应保留。
5. 看建议是否已发布、是否适用于当前设置、是否有效，以及开仓／维持／退出的条件。
6. 看计划损失、成本假设、止损止盈与失效条件；未知费用或资金费不能按 0 理解。

审核返回“需修改”时，作者可能在同一次研究里修改并再次送审；收到审核意见本身不代表获得授权。
只有真实发布并通过相应资格的可用建议，才可能进入模拟操作；报告显示完整也不能跳过账户与风险门。
旧报告可用于追溯，但不能作为当前新鲜行情或沿用旧授权的依据。

## 7. 手动模拟：先检查入口条件和当前缺口

**本轮实际模拟入场、退出、结算与成交截图：待验收。**
手动模拟只在页面给出可用入口时继续：BTC／ETH 的 4 小时建议有效、建议允许开仓、账户为空仓且可用保证金已核验。
保持建议卡片可见，点击 **“准备手动模拟”**；准备回执应对应当前账户、合约、设置和方案。
研究授权、保存设置和创建模拟账户都不能替代这笔模拟的独立确认。

**当前操作缺口：表单不展示实时买一／卖一，也没有实时报价辅助按钮。**
没有可靠、可追溯的当前报价与保护价时，普通用户应停在确认前，由维护人员协助核对；本手册不要求手填接口 JSON。
静态操作卡中的外部报价仅供独立核对，不能代替执行时的实际报价或成交回执。
系统会另取执行所需的新报价并检查资格，不满足条件可能“未成交”。

填写时逐项核对：

- **最多入场名义金额（USDT）**：本例不超过明确授权的 500，并受实际可用资金、最小张数与费用限制。
- **止损触发价／止盈触发价**：按页面价格步长填写真实保护价。做多：止损＜买入价＜止盈；做空相反。
- **最晚退出时间（本地时间）**：晚于当前时刻且不晚于方案有效期与研究窗口；留足填写、确认和报价时间。
- 金额、价格用普通十进制正数，按页面格式与价格步长要求填写；不要猜价格或为通过检查放宽 500／25。
- 再核对建议、方向和原准备回执，勾选本笔模拟授权，点击一次 **“确认这笔手动模拟”**。

确认结果不明时点“读取原回执”；已进入执行后用“读取模拟执行状态”。不要重新确认同一笔。

## 8. 分清排队、成交、退出和同账户 ETH

| 状态 | 含义与下一步 |
| --- | --- |
| 排队等待报价（queued） | 尚未成交，只读取原执行状态 |
| 已模拟成交（filled） | 核对实际张数、价格、手续费和成交回执，保留原记录 |
| 未成交（no_fill）／未获接受 | 阅读原原因；不能伪造价格、放宽限制或换账户强行通过 |
| 结果待核对 | 原结果未知，只恢复原回执 |
| 按原保护条件等待退出 | 仍有余仓；原止损、止盈或退出时间继续约束执行 |
| 余仓为 0 但结算未完成 | 不等于资金费和净收益已确认，等待实际结算 |

当前没有普通用户 **“立即平仓”** 按钮；执行方按原止损、止盈或最晚退出条件，用后续新报价处理退出。
必须核对余仓为 0、结算完成（settled）、账户空仓且余额已认证；资金费或净收益未知就保留未知。
遇到结算资料缺失，不要填 0，也不要另建账户冒充同账户复用成功。

BTC 完整退出、结算后，点 **“返回账户设置”** →“重新读取模拟账户”，仍选择原“模拟账户 1”。
选择 ETH 合约，核对账户支持 ETH、可用余额和 500／25，保存后重新读取设置，再发起一次 ETH 4 小时研究。
ETH 必须取得自己的新建议和新模拟授权，不能复用 BTC 的旧回执；BTC／ETH 共享原账户资金与保证金。

## 9. 失败、身份过期或旧数据怎样处理

1. 从原任务进入 **“查看原因与恢复”**，先读实际保存的错误与任务记录，不把通用提示当作根因。
2. 身份过期时通过正常本机入口恢复，等待身份回读，再核对原研究回执；不要重复发起。
3. 页面显示“未保存”报告时，不能把任务受理、后台材料或准备结果算作报告成功。
4. 旧材料、上次成功快照和旧进程状态只说明当时情况；先核对时间，必要时交由维护人员确认。
5. 原请求结果未知时保留原链接与请求编号；只有明确终态和恢复条件后，才考虑显式发起新研究。

## 10. 其他已有入口怎样使用

| 入口 | 可以做什么 | 阅读边界 |
| --- | --- | --- |
| 研究／研究主题 | 查任务、主题、旧报告、版本与变化 | 登记、排队和报告发布分别核对，旧主题不保证有新报告 |
| 资料 | 上传和核对原文、版本、审核与引用 | 上传、解析完成、允许引用与实际被研究使用是不同阶段 |
| 市场与事件 | 看事件日历、指标、来源和覆盖 | 核对时区、发布日与修订；缺失来源不能当成已覆盖 |
| 证据与原文 | 展开研究依据、来源和已保存原始响应 | 当前源网站内容可能已变，优先核对当时保存版本 |
| 管理与审计 | 查实际进程、来源任务、用量、历史记录 | 在线状态不等于研究成功；未知用量、成本不按 0 计算 |
| 效果跟踪／复查 | 查看既有判断、观察窗口和原计划 | 未到期不是失败，登记成功也不等于预测有效 |

自动多事件研究、完整事件覆盖与学习改进仍待验收，不应仅凭开关、图表或旧功能说明认定已实现。
其他历史功能的逐项说明和旧截图保留在下方备份；历史通过项不替代当前 BTC／ETH 核心验收。
