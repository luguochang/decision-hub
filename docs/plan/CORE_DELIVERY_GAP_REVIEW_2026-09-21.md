范围：DSH 真实研究链、证据来源、用户报告、分析链路可视化和交付边界

## 先给结论

当前系统已经可以交付为“证据化金融研究报告”，不能交付为“已验证胜率的自动交易系统”。这两个判断不再合并成一个状态。

最新真实 Run `run_d75406268ea74b2ab5223438826a483f` 证明主链已经贯通：8047 固定入口接收请求，Hub 创建 Run，DSH Web Host 执行研究，DSH 子 Agent 取得证据，Reviewer 复核，Hub 验证 Evidence 和 Gate，8047 回读报告。该 Run 有 12 条 accepted Evidence、5 个研究子 Agent、1 个 Reviewer，hard/soft coverage 均为 100%，没有重复轨迹或 worker 租约错误。

当前仍不能把报告称为高胜率模型，原因是 Reviewer 明确指出：日线与实时数据存在时间错位，衍生品只覆盖有限场所和短窗口，宏观变量没有样本外因果估计，概率没有校准、基准命中率和回测误差。因此报告可以给出“7 日规则方向偏多、已有现货持有倾向、空仓多头候选优先”的研究判断，但必须继续显示概率未校准和交易权限关闭。

## 发现的交付缺口

### 1. 来源有记录，但用户结果页不够集中

Evidence 卡片已经有来源链接和摘录，但来源数量、覆盖的需求、观测时间、新鲜度和 DSH 执行回执分散在图、Evidence 列表和技术详情中。用户容易看到一堆文本，却不能快速判断“这次到底用了多少来源、哪些来源支持哪个结论、数据是什么时候拿到的”。

处理：在用户结果页增加“可信度与来源”区，显示 DSH runtime/profile、研究轮次、工具调用、子 Agent、Reviewer、accepted/fresh Evidence、来源身份，并按 requirement 展示来源矩阵。矩阵只统计已通过 Evidence 校验的记录，并明确同一来源的多个接口不算多个独立来源。

### 2. 覆盖充分不等于预测可靠，页面需要主动说明

当前 `coverage=sufficient` 只表示本次要求的 Evidence 已满足，不表示方向预测已经验证。报告中已经有 `probability_status=unavailable/uncalibrated` 和 Reviewer limitation，但用户需要在首屏附近看到这条关系，而不是从技术详情推断。

处理：在可信度区固定显示“Evidence 覆盖通过不代表预测已校准”，继续把 `trade_authorized=false` 和概率未校准作为不可隐藏的状态。

### 3. DSH 能力已放开，但不能把预算上限误解成强制空转

DSH 当前启用 Skills、Goal、Todo、研究 subagent、连续 Session 和独立 Reviewer，预算为 10 轮、100 次工具调用、32 个子 Agent、1800 秒。研究 Manager 在证据充分且 Reviewer 没有可执行新缺口时可以提前结束；这属于有效停止，不是“只跑一轮”。

处理：保留当前 DSH 原生循环和预算上限，页面显示实际轮次、工具调用、子 Agent 和 Reviewer 数量。禁止为了看起来“深度”而强制重复检索，也禁止使用不存在的工具名或递归创建无限子 Agent。

### 4. 交付边界仍需写死

- 产品交付范围：最新 BTC 研究方向、当前行动候选、主链/反链、证据和复查条件。
- 当前不交付：自动下单、杠杆授权、60% 胜率承诺、未经校准的概率、把单一盘口代理称为全市场清算数据。
- DSH 3097 是运行/审计控制台；用户只用 8047。两个页面不是两套业务结论。
- 任何来源失败、过期、冲突、时间错位和 Reviewer 保留意见都必须保留在报告中。

## 验收标准

1. 空输入点击“获取最新操作建议”后，真实 DSH Web Host 完成或明确记录失败，不使用 fake/fixed fallback 冒充成功。
2. 用户结果页在首屏附近能看到方向、当前行动候选、执行权限、证据数量、来源数量、最新观测时间、DSH 轮次/工具/子 Agent/Reviewer 回执。
3. 来源矩阵中的每一条记录都能跳到原始 Evidence 或外部来源；Evidence 没有 URL 时必须跳到页面内摘录，不能生成伪链接。
4. 分析链路图显示真实 Evidence、主链、反链、Review、Coverage 和 Gate；流程图明确是结构化研究投影，不宣称逐字思维链。
5. `trade_authorized` 永远由确定性 Gate 控制；没有 CalibrationReceipt 时概率继续为 unavailable/uncalibrated。
6. DSH 出现 provider、工具或模型失败时，失败原因、影响范围和已保留证据仍可在技术详情中回读。
7. 前端测试、前端构建、后端全量测试和至少一次真实固定入口 Run 全部通过。

本文件完成后，本项目可以作为“可回读、可审计、有明确方向但不虚构胜率的研究产品”交付。若验收标准 5 或样本外校准目标未满足，不得包装成自动交易或高胜率产品。
