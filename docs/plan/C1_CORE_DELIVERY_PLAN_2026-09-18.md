# C1-CORE-DELIVERY：核心可交付目标

> 2026-09-19 更正：撤回本文件此前“核心研究建议已可交付”的结论。新发现旧快照锁定历史窗口、部分小时日聚合和单位标注错误；宏观尚未进入日频策略。工程用例通过不能替代研究价值验收。以 [当前方向整改](CURRENT_DIRECTION_CORRECTION_2026-09-19.md) 为准，下文旧完成状态仅作历史记录。

## 目标

把 Decision Hub 从“可复算的离线 7 日观点链路”推进到“可交付的研究产品核心”。交付对象是研究建议，不是自动交易系统：用户只输入“现在怎么操作”或留空补充，系统必须自动完成数据获取、策略计算、证据审计和报告展示。

交付链路：

`简单输入 → 7d 日频模式 → 实时/最近已闭合数据 → Fact → V0 策略 → 证据与反方 → research_outlook → UI 首屏`

## 交付边界

必须做到：

1. 至少一个公开、合法、可留档的日线源真实可达；当前价格和关键市场结构至少有一条真实可达路线。实时路线失败时必须在报告中显示来源、时间、错误类型和影响，不能把 replay 当 live。
2. 每次报告明确显示：方向、行动候选、触发条件、最强反方、失效条件、Evidence、数据限制、策略版本、概率状态和交易授权状态。
3. `research_outlook` 负责研究倾向，`trade_authorized=false` 负责交易边界；没有校准 receipt 时不显示胜率数字。
4. 至少完成一次真实 Run 的端到端回读：`run_id`、`artifact_id`、`strategy_receipt`、数据源、观测时间、输入 hash、Evidence、工具失败和 UI 首屏均可追溯。
5. 用五个核心案例验证价值：上涨趋势、下跌趋势、区间震荡、宏观/衍生品冲突、数据不足。每个案例必须产生明确方向或明确 unresolved，并能解释为什么。
6. 与简单基线做一次对照：基线只使用价格趋势或固定观望；Decision Hub 必须多出数值依据、反方、触发和失效条件。若没有可核验增量，停止产品投资，不继续堆 Agent 或页面。

明确不做：自动下单、扩大交易权限、伪造“最高胜率”、把论坛转载当事实、把订单簿代理写成清算事实、先做 PPT/角色入口/外围评测平台。

## 按现有代码的执行批次

### C1-A：真实数据供给和可观测失败

- 检查 `OKXHistoricalDataLoader` 的 1D 路径和 `HistoricalRefreshWorker.tick_daily()`；补第二条免费公开日线备用路由，优先使用官方交易所公开 API，不引入付费分钟数据。
- 检查当前 spot、funding、OI、basis 路由的字段、单位、观测时间和来源独立性；每条失败必须形成结构化 provider attempt。
- 真实执行一次 70~220 日窗口和一次当前市场快照；写入 data job、coverage、source id、content hash。
- 失败出口：两条公开路线均不可达，记录 `data_unavailable` 及影响，停止扩展，不用模型文本补齐。

### C1-B：研究观点和证据关联

- 在 `HistoricalDataResearchAdapter` 与 query view 之间保留 receipt hash、Evidence id、dataset、interval、as_of。
- 报告里的主因、反方和行动条件必须能指向具体 Fact/Evidence；没有对应 Evidence 就显示 unresolved 或数据限制。
- 将 funding/OI/basis/crowding 作为增强上下文，不能覆盖日频主策略，也不能把缺失增强数据改写成无理由的 no_trade。
- 在研究循环结束时保存一个结构化 synthesis receipt，记录每轮新增证据和观点是否变化。

### C1-C：真实主链和 UI 验收

- 使用固定入口触发真实 Run，完成 DSH/研究 worker/ Gateway/历史 adapter/策略/commit/query view/UI 回读。
- 首屏只突出当前 7 日观点和行动边界；技术详情继续显示过程、工具调用、失败原因、Evidence 和质量门。
- 记录 `run_id`、`artifact_id`、`strategy_receipt_id`、source ids、observed_at、数据 hash 和最终 recommendation。

### C1-D：五案例价值验收

每个案例固定同一信息边界，比较：

- `baseline`：只看收盘价趋势和固定观望规则；
- `decision-hub`：日频 V0 + 证据/反方/触发/失效。

验收只看可核验增量，不把历史命中率直接叫胜率：

- 上涨：不能被强制改成 no_trade，必须有偏多或等待确认；
- 下跌：必须有偏空或降低风险，不得自动推荐杠杆做空；
- 区间：必须显示区间/等待，概率为 null；
- 冲突：方向与入场风险分离，显示冲突来源；
- 数据不足：明确 unresolved 和受影响判断，不生成方向。

## 完成定义

- [~] 真实公开数据已成功写入一份日线 coverage；当前市场实时 Evidence 的公开网关仍失败，已在真实 Run 中保留结构化失败证据；
- [x] 真实 Run 端到端完成并可在 UI 回读；
- [x] 方向、主因、反方、行动、触发、失效和 Evidence 关联完整；
- [x] 五案例已完成结构性验收，实时数据不足案例明确为 `research_only`；
- [~] 已完成结构性基线对照，但尚无样本外命中率/校准证据，不能宣称预测增益；
- [x] 后端定向测试、前端测试、生产构建、契约检查和 Ruff 通过；
- [x] 开发日志记录真实运行证据、失败原因和遗留项；
- [x] `trade_authorized=false` 始终成立，未校准概率不显示胜率。

## 停止线

以下任一条件出现，目标停止并输出失败报告：

- 两条公开数据路线连续不可达，且无法建立可审计的 live/replay 分界；
- 真实数据可用，但五案例相对简单基线没有增量；
- 观点无法绑定到输入 hash、Fact 和 Evidence；
- UI 仍只显示“质量门失败”而没有方向或 unresolved 的具体原因；
- 为了得到方向而放宽 Gate、填充缺失数据或把主观概率写成校准概率。

## 下一步唯一动作

先执行 C1-A 的真实数据探针和当前市场快照，不先改外围功能。探针结果出来后再决定是修复公开数据路由，还是按停止线记录不可交付原因。

## 2026-09-19 状态冻结

本目标的核心研究建议出口已经达到可交付状态：固定短输入会进入 BTC 7d 日频模式；真实主链已取得 Gate.io/Huobi 双现货、Alternative.me 情绪和归档日线 Evidence；报告和 UI 能回读方向、行动、触发、反方、失效、来源、缺口、策略状态和 `trade_authorized=false`；旧版 30m/24h/72h 缺失不会再把已形成的 7d 观点显示成综合失败。

当前仍未达到交易研究出口，且这是明确的核心 Gate，不是待补的外围工作：`derivatives_crowding`（资金费率、OI、基差、拥挤度）仍没有可审计的公开路线，概率也没有样本外校准。因此当前产品可以交付为“有边界的 7d 研究建议”，不能交付为“可执行交易信号”。下一阶段若继续，只做一件事：补齐并验证衍生品/拥挤度数据路线；若连续不可达，保留当前研究交付并停止继续堆功能。
