# 01 — 产品需求

本文档定义 Decision Hub v3 的产品范围、用户场景、交付标准。架构、实现细节在其它文档。

---

## 1. 产品定位

Decision Hub 是**事前决策支持工具**，为加密货币交易者提供：

1. 基于宏观事件与市场状态的**方向概率估计**（向上/向下/区间）；
2. **多空方案对比**（含费用、资金费、止损/止盈、触发/失效条件）；
3. **根因链追踪**：从宏观数据 → 利率 → 跨资产 → 加密资金面 → 价格，每一环可验证；
4. **事件前预案与事后快速解读**；
5. **纸面交易验证**（PAPER）与**结果评分**，持续校准。

**不是：** 自动交易系统、信号推送服务、社交媒体机器人。用户自行决策与操作。

---

## 2. 用户角色

- **主要用户：** 有一定宏观理解、希望结构化自己判断的个人交易者。
- **典型场景：**
  - 看到 CPI 即将公布，想知道"超预期 / 符合预期 / 低于预期各自概率多少、对 BTC 影响多大、该做多做空还是等待"；
  - 市场无明确事件，想知道"未来 4h 上涨/下跌/区间的概率、建议操作"；
  - FOMC 前一天，想看"各种利率决策情景下的 BTC 反应预案"；
  - 一周后想复盘"上次判断对了哪几环、错了哪几环、系统胜率是否在提高"。

---

## 3. v3 范围（最终交付标准）

### 3.1 资产与期限

- **资产：** BTC-USDT-PERP、ETH-USDT-PERP（OKX）
- **期限：** 4h、24h、72h
- **组合：** 2 × 3 = 6 个

### 3.2 市场类型

- **普通市场：** 无重大已知事件，基于当前行情、拥挤度、宏观背景给出判断。
- **事件研究：** 针对 FOMC、CPI、PCE、NFP、GDP 等重大事件，给出事前预案（各情景 p 及条件方向 q）与事后解读。

### 3.3 功能清单

| 功能 | Phase | 最终要求 |
|---|---|---|
| 研究发起与调度 | 2 | 用户手动发起、定时自动、条件触发（价格/事件） |
| 普通市场方向概率 | 2 | 上涨/下跌/区间，三者概率和=1，展示基率/市场锚点/系统估计 |
| 根因与证据 | 2 | 结构化：关键证据 ≥3 条、反证 ≥1 条、来源可追溯 |
| 多空方案对比 | 2 | 含 Taker 费用、预期资金费、入场价、止损/止盈、预期收益与风险 |
| 触发与失效条件 | 2 | 价格条件、时间条件、事件条件 |
| 独立审核 | 2 | 反方视角审核，可退回修订 |
| 事件因果图 | 4 | CPI/PCE/NFP/FOMC/GDP 各一套固定模板，每环输出当前状态与预期变化 |
| 事件前预案 | 4 | 提前 24—72h 生成，覆盖主要情景 |
| 事件后解读 | 4 | 数据公布后 5 分钟内，输出惊喜方向、传导链实时状态、预案是否触发 |
| 条件监控与提醒 | 5 | 触发/失效条件、拥挤度预警、事件阶段变化 |
| PAPER 全生命周期 | 6 | 确认 → 成交 → 持仓 → 止损/止盈/到期 → 结算 → 结果归档 |
| 预测评分 | 7 | Brier、log loss、可靠性曲线，按资产/期限/事件族分层 |
| 经验学习 | 7 | 结果归因到因果图节点，抽取经验，人工批准后进入下轮输入 |
| PC 端 | 全程 | 报告展示、研究发起、PAPER 操作、历史查询、复盘中心 |

### 3.4 明确不做（v3 范围外）

- 真实下单（只做 PAPER）
- 手机端、公开 API、多用户
- BTC/ETH 之外的资产（黄金、纳指、恒指等留待 v4）
- 社交媒体发布
- Kronos 类多策略组合

## 4. 合格研究定义

一次研究同时满足以下全部条件才算**合格**：

1. **信息集冻结：** 所有引用数据的 `known_at` 早于研究决策时点；
2. **概率完整：** 给出方向概率（普通市场）或 p + q（事件研究），概率和 = 1、与期限匹配；
3. **证据结构化：** 关键证据 ≥ 3、反证 ≥ 1、来源可追溯；
4. **方案含成本：** Taker 费用、资金费、止损/止盈、触发/失效；若结论为"观望"，必须写明转为可操作的条件；
5. **通过独立审核：** 允许退回修订后通过；
6. **可读可存：** PC 上可读，重启后仍可读。

**不合格的：** degraded、有限结果、仅材料、审核拒绝、PC 读取失败。

---

## 5. 最终交付标准

v3 视为可交付，需同时满足：

### 5.1 稳定性

- BTC/ETH × 4h/24h/72h 六个组合，连续 **14 个自然日**，自动+手动研究合格率 ≥ **90%**；
- 单次研究端到端时间 ≤ 15 分钟（P50），≤ 30 分钟（P95）；
- 条件监控触发后继研究，合格率 ≥ 90%；
- 重启后所有历史报告可读、PAPER 持仓正确恢复。

### 5.2 预测评估

- 至少 **2 类事件族**（如 CPI + FOMC）在真实事件中完成 事前预案 → 数据落地 → 情景判定 → 方案更新 全流程；
- 累积 ≥ **4 周** 的预测评分报表（Brier、log loss、分层统计）；
- PAPER 正式成交 ≥ **10 笔**，覆盖止损、止盈、到期退出、重启恢复；流水与 OKX 行情可对账。

### 5.3 文档与可维护性

- **用户手册：** 研究发起、报告阅读、PAPER 操作、复盘中心使用；
- **运维手册：** 启动、停止、升级、回滚、备份、日志查看、常见错误处理；
- **交接清单：** 代码结构、配置项、数据库表、API 端点、测试运行方法。

### 5.4 质量门禁

- Python 代码 ruff + pyright strict 零错误；
- 单元测试覆盖核心逻辑（概率计算、成本、状态机、因果图）；
- 至少 **30 个历史回放用例**（真实失败场景录制）全部通过；
- 所有合格研究可在 PC 上一键导出为 JSON + HTML 自包含报告。

## 6. 用户场景示例

### 场景 A：普通市场 4h 判断

**输入：** 用户在 PC 上选择 BTC 4h，点击"发起研究"。

**过程：**
1. 系统采集最新 K 线、资金费率、OI、跨资产日线、宏观日历；
2. 计算历史基率、读取期权隐含波动（市场锚点）；
3. LLM 研究：补充证据 → 情景推理 → 给出相对锚点的概率调整；
4. 独立审核：反方视角，若有重大遗漏退回；
5. 生成报告：首屏展示方向/概率/建议操作/根因三条；审计信息折叠。

**输出：** PC 显示报告，用户看到"上涨 45%、下跌 25%、区间 30%；建议做多，入场 82300、止损 81500、止盈 83500，触发条件：突破 82500；失效：DXY 突破 107"。用户可点击"PAPER 确认"模拟成交。

**合格判定：** 信息集 known_at 合规、概率和=100%、证据≥3+反证≥1、审核通过、PC 可读 → **合格**。

### 场景 B：CPI 事件预案

**输入：** 系统监控到 CPI 公布时间为 10 月 25 日 20:30，提前 48h 自动发起事件研究。

**过程：**
1. 读取共识（预测市场、经济学家中位数）、FedWatch 利率概率、期权隐含跳动；
2. 按因果图模板：CPI 惊喜 → 利率预期 → 美债收益率 → 风险资产 → ETH；
3. 情景划分：超预期（p=35%）、符合（p=50%）、低于（p=15%）；
4. 每个情景给出条件方向 q、传导链各节点预期变化、建议操作；
5. 审核通过，发布预案卡。

**输出：** PC 显示预案卡，用户事前就知道三种情景各自的操作清单。数据公布后 5 分钟，系统自动输出"实际 3.2% vs 共识 2.9%，超预期，利率预期已上升 8bp，美债收益率 +5bp，ETH -1.2%，预案情景 1 触发，建议做空已生效"。

## 7. 非功能需求

- **时点完整性：** 所有研究可回放，回放结果与实时一致（除模型随机性）。
- **费用透明：** 每次研究记录模型调用次数、token、费用；PC 可查询。
- **可审计：** 原件、证据、审核意见、概率来源、PAPER 流水全部可追溯。
- **隐私：** 用户数据（PAPER 持仓、设置）本地存储，不上传。
- **响应：** PC 操作响应 < 500ms（查询类）、< 2s（提交类）。
