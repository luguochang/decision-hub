## 二、方法论亮点

### 1. 约束执行智能体的核心机制

**问题：** Codex 之前写的代码导致了当前的失败状态，它会重复同样的错误（过度工程、校验压倒业务、版本混乱）。

**解决：**
- **AGENTS.md 第 2 节"绝对禁止"：** 15 条铁律，包括禁止修改旧代码、禁止 import 旧模块、禁止编造数字、禁止为通过测试而放宽断言、禁止文件名带版本号、禁止新增依赖未批准。
- **任务卡"允许修改的路径"：** 白名单机制，只能改任务卡列出的文件/目录。
- **任务卡"禁止事项"：** 明确本任务不应该做的事（防止执行智能体"我觉得更完整"而加功能）。
- **验收命令：** 可复现、可自动化检查，不依赖主观判断。
- **报告"已知问题/偏离"：** 强制诚实，隐瞒比失败更严重。

### 2. 分层设计驱动开发

- **需求（01）→ 架构（02）→ 数据契约（03）→ 预测方法（04）→ 阶段计划（05）→ 任务卡：** 每层清晰、可验证、单一职责。
- 执行智能体拿到的任务卡是"叶子节点"，无需理解全局，只需按卡执行。
- 架构师负责全局一致性，执行智能体负责局部正确性。

### 3. 阶段串行、任务并行

- Phase N 未完成前不开工 Phase N+1（防止地基不稳时盖高楼）。
- 同一 Phase 内独立任务可并行（例如 Feature Store 和 Forecast Engine 的单元测试可以同时写）。
- 每个 Phase 有明确验收标准（定量 + 定性），架构师写阶段验收报告后才能进入下一阶段。

### 4. 回放优先于付费运行

- Phase 0 就建立回放框架（cassette 录制/回放）。
- 真实运行失败后，必须先用录制写一个回放测试能复现，修复后回放测试通过，才允许再进行真实运行。
- 历史回放评估可以在几周内积累数百个样本，比等实时运行快得多。

### 5. 概率分层与市场锚点

- 基率 → 市场锚点（预测市场/期权隐含）→ LLM 证据调整 → 校准器，每层可验证、可替换。
- 只有系统估计与市场共识差异显著且有证据时，才给出方向性方案。
- 这是 `OPTIMIZATION_AND_EXTENSIONS.md` 第 3.2 节的核心，也是 v3 与 v1/v2 的根本区别。

## 四、关键风险与应对

### 风险 1：执行智能体不遵守 AGENTS.md

**现象：** Codex 可能会"我觉得这样更好"而修改任务卡范围外的文件、加未要求的功能、import 旧模块。

**应对：**
- 每个任务验收时，架构师检查 git diff，确认只修改了允许的路径。
- 第一次违反：REJECTED，要求严格按任务卡重做。
- 第二次违反：更换执行智能体会话，或在新会话开头强调 AGENTS.md。

### 风险 2：任务卡不够具体，执行智能体 BLOCKED

**现象：** 任务卡有歧义、缺边界条件、缺错误处理说明，Codex 写 Question。

**应对：**
- 架构师在编写任务卡时，参考 T-000 的详细程度（6.9 KB）。
- Question 出现后，快速裁决（<24h），避免阻塞链条延长。
- 前几个任务的 Question 汇总成"常见设计决策"FAQ，后续任务卡引用。

### 风险 3：Phase 0 实测发现工期低估

**现象：** T-001—T-007 实际工时超出预期 50% 以上。

**应对：**
- Phase 0 作为"校准阶段"，允许工期偏差。
- Phase 0 完成后，架构师根据实际工时重新估算 Phase 1—8。
- 若总工期超出用户预期（如超过 20 周），与用户讨论是否缩减范围（如只做 4h、不做 72h）。

### 风险 4：历史回放样本不足

**现象：** 旧正式库只有 14 条成功 Run，失败的 Run 中很多是协议错误、无法提取为有效样本。

**应对：**
- Phase 0 的回放框架先用 mock 数据验证能工作。
- Phase 2 开始后，每次真实运行都录制 cassette，逐步积累。
- 如果旧库实在没有可用样本，Phase 7 的历史回放评估改为"Phase 2—6 积累的样本"。

## 五、成功标准（重申）

v3 视为可交付，需同时满足（来自 `01_REQUIREMENTS.md` 第 5 节）：

1. **稳定性：** BTC/ETH × 4h/24h/72h 六个组合，连续 14 天，合格率 ≥ 90%；单次研究 P50 ≤ 15 分钟、P95 ≤ 30 分钟。
2. **预测评估：** ≥ 2 类事件族完成事前预案 → 数据落地 → 情景判定全流程；累积 ≥ 4 周评分报表；PAPER ≥ 10 笔成交。
3. **文档：** 用户手册、运维手册、交接清单。
4. **质量：** ruff + pyright strict 零错误；≥ 30 个历史回放用例全部通过；合格研究可一键导出 JSON + HTML。
