# Decision Hub v3 重建计划

本目录包含 Decision Hub v3 的完整设计、任务分解、验收标准与进度跟踪。

## 背景

v1/v2（代码位于 `packages/kernel/`、`apps/hub_*`、`extensions/dsh/decision-hub/`）在 2026-10 已无法稳定交付：257 次研究 0 成功，架构、流程、质量控制均存在根本性问题。详见 `docs/diagnosis-2026-10-23/DIAGNOSIS_AND_SOLUTION.md`。

v3 是完整重建，不是修补。目标：可验证、可交付的事前决策支持产品。

## 核心原则

1. **功能最小，质量最高。** 先做到 BTC/ETH × 4h 普通市场每天稳定出合格报告，再扩展期限、事件、监控。
2. **验收驱动开发。** 每个任务的"完成"定义在任务卡中，必须能用命令验证，不能靠主观判断。
3. **阶段串行，任务并行。** 阶段 N 未完成前不开工阶段 N+1；同一阶段内独立任务可并行。
4. **回放优先于付费运行。** 真实模型调用必须先有对应的回放测试能复现场景。
5. **概率分层，LLM 不直接给交易概率。** 基率 → 市场锚点 → LLM 证据调整 → 校准器，每层可验证、可替换。
6. **因果图先行。** 每个事件族定义传导链模板，研究输出按节点填充，事后按节点评分。
7. **时点严格。** 所有数据按 `known_at` 索引，研究/回放从统一接口读取，绝不出现"用未来信息"。

## 角色分工

- **架构师/产品负责人（本会话）**：设计、任务分解、验收标准、问题裁决、阶段验收。
- **执行智能体 Codex（其它会话）**：按任务卡执行、写测试、写代码、提交报告。只能做任务卡允许的事，不得自行补全设计。
- **用户（人类）**：最终验收、优先级决策、授权数据源、上线批准。

## 执行流程

1. 架构师写完一批 READY 任务后，通知执行智能体。
2. 执行智能体按 `AGENTS.md` 规则，一次拿一个 READY 任务，切分支、写测试、实现、验收、提交报告。
3. 架构师验收：ACCEPTED 合并到 `v3/main`；REJECTED 附意见，执行智能体修复后重新提交。
4. 任务完成后执行智能体结束会话；架构师需要时再通知开始下一任务。
5. 阶段内所有任务 ACCEPTED 后，架构师写阶段验收报告，决定是否进入下一阶段。

## v3 与旧代码的边界

- v3 新代码位于：`packages/core_v3/`、`apps/api_v3/`、`apps/worker_v3/`、`apps/pc_v3/`、`tests/v3/`、`data/v3/`、`migrations_v3/`。
- v3 **禁止** import 旧模块（`packages/kernel/`、`packages/runtime_adapters/`、`packages/orchestration/` 等）。需要旧逻辑时移植（复制代码并在文件头注明来源）。
- 旧代码、旧数据库、旧服务保持只读，不触碰。允许只读查询旧正式库用于历史回放样本采集（需任务卡明确授权且用 `mode=ro`）。
- v3 使用独立的数据库文件、端口、进程。
