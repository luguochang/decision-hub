# 从生成设计图到可实现界面的业务修正

此文不是对原产品代码的审计结论。依据是用户提供的 S1 交接稿及本次会话的生成设计图；未读取或运行当前仓库后端。以下对生成图中的错误予以明确记录，不静默把它们当作原产品已有逻辑。

| 生成图里的表现 | S1 支持的内容 | 本交付如何处理 |
|---|---|---|
| 报告显示 62% 置信度，且“校准正常”，另一处又是 uncalibrated | 第 7 页明确概率可能未校准；没有提供 62% 的根据 | 报告显示未校准，不编造胜率；覆盖率是 9/12 的演示需求覆盖，不是预测概率 |
| Gate 已通过，看起来意味着交易可执行 | 第 7、12 页将研究方向、执行许可区分；可为 research_only | 分开显示研究结果可读、未校准、交易未授权；偏多不变成买入按钮 |
| 30m / 24h no_trade 被解释成缺少分析 | 第 7 页明确不能如此渲染 | 保留 no_trade 并说明当前未满足行动条件；允许查看限制与触发条件 |
| completed、failed 像一条顺序时间线 | 第 4–5 页分别列成功和失败状态 | 失败作为分支，保留失败来源与重试入口，原始记录不覆盖 |
| “自动去重”可以关闭，还暗示相似问句必然合并 | 第 4 页只有同内容、同窗口的幂等要求 | 幂等保护不可关闭；不宣称实现语义相似去重；模拟窗口值写入说明 |
| Word / CSV / URL 作为已经支持的上传格式 | 第 10 页只列 PDF、PNG、JPG、WEBP、TXT、MD、HTML | 原型按明确格式校验；50MB 是设计示例限制，生产需读取服务配置 |
| 解析 65% 与修正完成、质量通过同时出现 | 第 10–11 页需要独立过程状态 | 解析、待审核、人工确认、质量复检、可接入分别实现 |
| 把 “likely” 删除、或修改权限结论后，仍显示事实一致通过 | 第 10 页要求原文保留与人工确认，没有授权系统改写事实 | 本原型用“未→已”的权限改写演示风险阻断；不允许接受该高风险建议 |
| “公开（团队可见）”与“内部（仅本组织）”含义不清 | 第 10 页要求隐私模式，但没有给枚举与可见范围 | private / organization 是 UI 提案，真实枚举待后端确认；不擅自新增公开互联网发布 |
| 宏观历史页填入未来事件，缺失值或版本被覆盖 | 第 5–6 页要求历史空态真实，修订不覆盖旧值 | history=0 时明确“尚未采集历史发布”；缺失显示 —；版本独立字段 |
| 返回只画了箭头，没有来源、筛选和滚动状态 | 第 2、9 页要求同 Run 与返回原位置 | 实际 URL 保存 back；筛选变更同步更新 drill-down 返回地址；保存滚动和焦点 |
| DSH 在每页主导航里像第二个产品首页 | 第 1、12 页明确仅技术排查 | 从当前 Run 的技术页进入，有内部提示及回到同一技术页的入口 |
| 示例 URL、市场价、事件时间看起来像真实采集值 | S1 没有给出生成图中全部数值和链接的证据 | 不继承伪链接和未经支持的数字；演示数据全局及局部标识 |
| 来源降级与 Worker 全绿被混为一个“系统正常” | 第 3、13 页要求 unknown / degraded 明确 | Worker、来源和执行许可三种语义独立，不用单个绿勾替代 |

## 本次新增的设计提案

关键词 / 筛选保存在 URL、报告触发点焦点恢复、资料与新 Run 双向关联入口、手机端模块重排、页面目录、资产目录，是为了让流程完整而作的 UI 提案，不代表原后端已经具有相同字段或接口。

S1 提到“重新研究不覆盖旧报告”；原型进一步显示父子关系。失败重试的具体执行语义在后端合同缺失时不能确定：这里用新子 Run 模拟，联调时需核实是新 Run、同 Run attempt，还是 observation 幂等返回。
