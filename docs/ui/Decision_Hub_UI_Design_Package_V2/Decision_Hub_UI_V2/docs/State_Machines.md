# 状态与数据边界

## 研究任务

```text
可选输入 → submitting → queued → researching → completed
                 ↘ failed       ↘ failed
completed：还需读取 report_kind，不能单凭任务成功判断结论完整
```

`completed + research_only` 表示研究结果可读，但不是交易授权；`completed + synthesis_incomplete` 表示任务已结束但因果论证不完整。`no_trade` 是某个周期的行动候选，不是任务失败状态。`uncalibrated` 属于概率状态，不能放进交易权限字段里。

提交先锁定输入和按钮。同一窗口、同一归一化内容、同一资料版本 / parent 意图复用幂等键。原型使用 60 秒演示窗口并保存在本地会话；生产幂等性必须在服务端保证，客户端锁按钮不够。不得用任意文本相似度合并用户的不同研究意图。

由用户在当前进度页启动的任务完成后，原型进入对应报告；用户已经离开时不强制切走，而让任务在列表完成。后一条是对避免打断的设计补充。模拟计时器不代表真实 Worker 能力，也不提供跨标签页、关页后的持续执行保证。

## 资料版本

```text
uploading → parsing → review / quality_insufficient
              ↘ failed
review → [逐块决策完成 + 显式确认] → confirmed → quality_recheck
quality_recheck → ready → linked_to_run
                    ↘ 质量不足时回到可定位的缺口
```

原始文件和原始块不可变。每个修正决策针对 `version_id + block_id`；确认后生成新版本，不能覆盖旧版本。人工确认、服务端质量门和研究任务创建是三个独立动作。前端按钮不可用只是提示，不是安全边界。

本地模拟只存储文件名、格式、大小及表单元数据，不上传字节，也不真正读取 / 解析用户文件。侧面展示的差异来自固定演示文本。将来真实接入时需添加上传凭证、解析作业、版本并发、质量门和关联合同。

## 日历和健康状态

事件的发布时间、数据采集状态、前值、预测、实际值和版本分别存在。`actual=null` 不等于 `0`；`history=[]` 不等于请求失败。当前缺乏历史时说明覆盖范围与最后成功时间；S1 中的 BLS 403 是截图当时的情况，不在本包中伪装为实时监测事实。

`online`、`unknown`、`degraded` 是运行 / 来源维度的语义。未知不渲染成健康，数据源降级也不必意味着所有 Worker 下线。数据过期应按来源和受影响研究范围表达。

## 原型中故意不实现的能力

不连接实时行情、自动下单、模型执行、真实 OCR、云端文件持久化、身份权限、团队协作或秘密日志。不存在真实数据时不补造交易结论；API 合同缺失的部分列在 `API_Contract_Map.md`。
